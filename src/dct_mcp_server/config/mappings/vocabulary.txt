# Vocabulary translation map (PPM-1129)
#
# Applied by tools/core/vocabulary.py:to_canonical() to text that originates
# upstream and is shown to a user -- raw DCT/engine error bodies (pre-built
# tools and the dynamic execute tool, surfaced additively as
# message_for_user), and OpenAPI operation summaries surfaced by the dynamic
# discovery tool and the keyword-fallback confirmation prompt. Internal
# terminology on the left, the canonical customer-facing term on the right.
#
# Format: internal_term|canonical_term[|guard=word,word...]...
#
# Matching is case-insensitive and whole-word. The canonical term keeps its
# authored casing mid-sentence, is capitalised at a sentence start and
# upper-cased when the match was all caps.
#
# Never translated, whatever the term: URLs, anything containing "/" (API and
# file paths), hyphen/dot-joined identifiers (tf-1, delphix-postgres-plugin)
# and {placeholders}. Those are machine identifiers, not prose.
#
# Optional guards, for words that also have an unrelated everyday meaning:
#   skip_if_preceded_by=w1,w2   leave the match alone after one of these words
#   skip_if_followed_by=w1,w2   leave the match alone before one of these words
#   only_if_text_mentions=w1,w2 apply this line only if the whole text mentions
#                               one of these (prefix match: "profil" matches
#                               "profiling"); otherwise fall through to the
#                               next line for the same term, if any
# Several lines may share an internal term; the first applicable one wins.
#
# Output must be text a customer can read as-is. Never put an instruction to
# the model ("clarify which") in the canonical column -- conversational rules
# belong in config/server_instructions.md.
#
# Reconciled against the real DCT_MCP_Server_Vocabulary_Glossary_v1.2.xlsx
# (28 canonical terms, 172 synonym rows). See config/server_instructions.md
# for the full domain model.

# --- "Delphix engine" (glossary #8) ---
# Forbidden, and ambiguous between the two engine products; the glossary
# forbids defaulting to one. Resolve from the text itself where it says which
# kind of work is involved (masking vs. virtualization); when it names both or
# neither, say exactly what is known -- one of the two -- in plain customer
# language. The model is told in server_instructions.md rule 2 to pin it down
# from conversation context or ask. Do not re-introduce a single-product
# default, and do not put a model instruction ("clarify which") in the output.

# --- Retired Continuous Compliance terminology (glossary #27) ---
# "inventory" is retired only as the name of the Continuous Compliance object
# now called a rule set. The everyday word is still live elsewhere in
# upstream text -- DCT's "VDB inventory report" (a Continuous Data report
# listing VDBs, /reporting/vdb-inventory-report) and an Oracle "central
# inventory" (oraInventory) during environment discovery -- so translate only
# when the text is about masking/compliance, and never in those phrases.
# "domain" (glossary #26) is deliberately not mapped: the glossary says to keep
# it until the Continuous Compliance UI migrates.
