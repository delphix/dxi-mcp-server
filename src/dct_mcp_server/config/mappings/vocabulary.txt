# Vocabulary translation map (PPM-1129)
#
# Applied by tools/core/vocabulary.py:to_canonical() to text that originates
# upstream and is shown to a user -- raw DCT/engine error bodies (pre-built
# tools and the dynamic execute tool, surfaced additively as
# message_for_user), and OpenAPI operation summaries surfaced by the dynamic
# discovery tool and the keyword-fallback confirmation prompt. Internal
# terminology on the left, the canonical customer-facing term on the right.
#
# Format:
#   @signals name=w1,w2,...                       declare a named word set
#   internal_term|canonical_term[|guard=w1,w2...]...
#
# Matching is case-insensitive and whole-word. The canonical term keeps its
# authored casing mid-sentence, is capitalised at a sentence start and
# upper-cased when the match was all caps.
#
# Never translated, whatever the term: URLs, anything containing "/" or "\"
# (API, POSIX and Windows paths), hyphen/dot/@-joined identifiers (tf-1,
# delphix-postgres-plugin, toolkit@1.0.0) and {placeholders}. Those are
# machine identifiers, not prose.
#
# A substitution never doubles a term: if the neighbouring words already spell
# part of the canonical term ("VDB containers"), they are merged into it
# ("VDB Groups"), never repeated ("VDB VDB Groups").
#
# Guards. Words are whole-word and case-insensitive (a phrase's spaces also
# match a hyphen: "self service" matches "self-service"); "@name" expands to a
# declared signal set. No prefix or substring matching -- "profil" would match
# "profile", and "inventory" would match "VDB inventory report".
#   only_if_text_mentions=...  POSITIVE CONTEXT: apply this line only if the
#                              text contains one of these words.
#   skip_if_text_mentions=...  do not apply this line if the text contains one
#                              of these words.
#   skip_if_preceded_by=...    leave a match alone right after one of these
#   skip_if_followed_by=...    leave a match alone right before one of these
# Several lines may share an internal term; the first line whose text
# conditions hold wins, the rest are ignored for that text.
#
# Words with an everyday meaning ("container", "inventory") or an ambiguous
# referent ("Delphix engine") are translated only on POSITIVE evidence that
# they carry the retired Delphix meaning. Do not "fix" a false positive by
# adding words to a skip list: an exception list is only ever as good as the
# examples someone thought of. Tighten the positive signal instead.
# tests/unit/test_vocabulary_spec_corpus.py runs every summary and description
# in a real DCT OpenAPI spec through the translator to catch regressions.
#
# Output must be text a customer can read as-is. Never put an instruction to
# the model ("clarify which") in the canonical column -- conversational rules
# belong in config/server_instructions.md.
#
# Reconciled against the real DCT_MCP_Server_Vocabulary_Glossary_v1.2.xlsx
# (32 Canonical Terms rows -- #1-#28 plus 3a, 7a, 7b, 19a -- and 169 Synonym
# Map rows). See config/server_instructions.md for the full domain model.

# --- Retired Continuous Compliance terminology (glossary #27) ---
# "inventory" is retired only as the old name of the Continuous Compliance
# object now called a rule set. The everyday word is live elsewhere in
# upstream text: DCT's "VDB inventory report" (a Continuous Data report), the
# migratable-job inventory, an Oracle central inventory, and -- in current DCT
# text -- a rule set's own table/column inventory ("the rule set's
# inventory"). So translate only on positive evidence that the text is about
# masking, and never when the text already uses the current term "rule set":
# then "inventory" is a part of the rule set, not a name for it, and
# translating would produce "the rule set's rule set".
# "domain" (glossary #26) is deliberately not mapped: the glossary says to keep
# it until the Continuous Compliance UI migrates.
inventory|rule set|only_if_text_mentions=@compliance|skip_if_text_mentions=rule set,rule sets,ruleset,rulesets
inventories|rule sets|only_if_text_mentions=@compliance|skip_if_text_mentions=rule set,rule sets,ruleset,rulesets
