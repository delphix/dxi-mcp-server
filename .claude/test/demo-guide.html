def test_job_tool_search_routes_to_jobs_search_endpoint(mock_dct_client):

    assert call_args.args[0] == "POST"
    assert call_args.args[1] == "/jobs/search"
    assert call_args.kwargs["params"]["limit"] == 10

@respx.mock
async def test_client_retries_on_5xx_then_succeeds():
    route = respx.get("https://dct.test/dct/v3/jobs").mock(side_effect=[
        httpx.Response(503, json={"error": "unavailable"}),
        httpx.Response(503, json={"error": "unavailable"}),
        httpx.Response(200, json={"items": [{"id": "j-1"}]}),
    ])
    client = DCTAPIClient()
    result = await client.make_request("GET", "jobs")
    assert route.call_count == 3, "should have retried twice before succeeding"
    assert result == {"items": [{"id": "j-1"}]}

3b — Workflow ★ (the headline test)

The exact replacement for hand-driving Claude Desktop. Translates .claude/test/testing/self_service.md lines 12–17 (search → get → start → stop) into one deterministic Python test.

async def test_vdb_lifecycle_search_get_start_stop(
    mcp_client_self_service, dct_stub
):
    # Step 1 — Search for all VDBs
    search_result = await mcp_client_self_service.call_tool(
        "data_tool", {"action": "search_vdbs", "limit": 10}
    )
    assert dct_stub.received_request("POST", "/dct/v3/vdbs/search")
    items = _payload(search_result).get("items", [])
    vdb_id = items[0]["id"]

    # Step 2 — Get that VDB's details
    get_result = await mcp_client_self_service.call_tool(
        "data_tool", {"action": "get_vdb", "vdb_id": vdb_id}
    )
    assert dct_stub.received_request("GET", f"/dct/v3/vdbs/{vdb_id}")

    # Step 3 — Start that VDB
    await mcp_client_self_service.call_tool(
        "data_tool", {"action": "start_vdb", "vdb_id": vdb_id}
    )
    assert dct_stub.received_request("POST", f"/dct/v3/vdbs/{vdb_id}/start")

    # Step 4 — Stop that VDB (requires confirmation, so we pre-confirm)
    await mcp_client_self_service.call_tool(
        "data_tool",
        {"action": "stop_vdb", "vdb_id": vdb_id, "confirmed": True}
    )
    assert dct_stub.received_request("POST", f"/dct/v3/vdbs/{vdb_id}/stop")

The "that VDB" chaining from the .md file becomes the vdb_id Python variable. Every step is a real MCP call. Every step is verified at the wire level.

3c — Confirmation handshake

Proves the destructive-op two-step contract survives end-to-end through MCP stdio. First call returns confirmation_required without hitting DCT; second call with confirmed=True actually issues the destructive request.

async def test_delete_vdb_two_step_confirmation(mcp_client_self_service, dct_stub):
    vdb_id = "v-1"

    # Step 1 — first call must NOT execute
    first = await mcp_client_self_service.call_tool(
        "data_tool", {"action": "delete_vdb", "vdb_id": vdb_id}
    )
    body = _payload(first)
    assert body.get("status") == "confirmation_required"
    assert body.get("confirmation_level") == "manual"
    assert not dct_stub.received_request("POST", f"/dct/v3/vdbs/{vdb_id}/delete")

    # Step 2 — confirmed=True triggers the actual call
    await mcp_client_self_service.call_tool(
        "data_tool", {"action": "delete_vdb", "vdb_id": vdb_id, "confirmed": True}
    )
    assert dct_stub.received_request("POST", f"/dct/v3/vdbs/{vdb_id}/delete")

How the dct_stub works

# tests/fixtures/dct_stub.py
class DctStub:
    def __init__(self):
        self.requests = []  # records every (method, path, body)

    async def vdbs_search(self, request):
        await self._record(request)
        return JSONResponse({"items": _FIXTURE_VDBS})

    async def vdb_job_action(self, request):
        await self._record(request)
        return JSONResponse({"job": {"id": "j-1"}})

    def received_request(self, method, path):
        return any(m == method and p == path for m, p, _ in self.requests)

Real production fragility this layer already caught

While building the workflow test, it surfaced a latent bug: async_to_sync in the tool modules calls asyncio.run() in a per-call thread, which closes the event loop between MCP calls. The cached httpx.AsyncClient dies on the next call. The retry loop recovers, but each call ends up on the wire twice.

Manual Claude Desktop testing never would have surfaced this — but the workflow test sees it instantly via duplicate stub recordings. Worth a follow-up PR after the demo.

The cleanup placeholder

PoC tests are read-only so cleanup is a no-op. Scaffold exists for when destructive workflows are added — every created resource gets tagged with E2E_RUN_TAG (e.g. e2e-a1b2c3d4-1716...) and the cleanup pass searches for and deletes anything matching the current run's tag. Forced to run via if: always() in CI so crashed runs still clean up.

  • Validates real auth (API key format change, ACL drift)

Why not on every PR? Real DCT is slower than the stub, requires reachable network, and adds flake risk (real transient errors). Layer 3 (the stub-based functional tests) is what gates merges. Layer 4 is a periodic confidence check, not a per-commit gate.

The Break Demo — The Emotional Moment

The goal: show that a one-line regression is caught instantly with a clear, actionable error message. This is what makes the value of CI visceral.

Step 1 — Make the breaking change

Open src/dct_mcp_server/tools/dataset_endpoints_tool.py, find the search_vdbs action (around line 2705), and change:

return make_api_request('POST', '/vdbs/search', params=params, json_body=body)

to:

return make_api_request('POST', '/vdbs/search-BROKEN', params=params, json_body=body)
